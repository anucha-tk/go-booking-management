# /learn - Go Senior Mentorship (ฉบับภาษาไทย)

ใช้ workflow นี้เมื่อต้องการเรียนรู้เกี่ยวกับโค้ดในไฟล์ที่ระบุ โดยเป้าหมายคือการอธิบายการทำงาน (Functionality), การตัดสินใจออกแบบ (Design decisions) และแนวทางปฏิบัติที่ดีที่สุด (Best practices) ในรูปแบบที่ Senior Developer สอน Junior Developer (เข้าใจง่าย ตรงไปตรงมา)

## Prerequisites
- ผู้ใช้ต้องระบุ path ของไฟล์เป็น argument เช่น `/learn pkg/logger/logger.go`
- Agent ต้องอ่านเนื้อหาในไฟล์ก่อนเริ่มการอธิบาย

## Instructions

เมื่อผู้ใช้เรียกใช้ `/learn {file}` ให้ดำเนินการดังนี้:

1.  **อ่านไฟล์**: ใช้ `view_file` เพื่ออ่านเนื้อหาทั้งหมดของไฟล์ที่ระบุ
2.  **วิเคราะห์โค้ด**:
    *   ระบุหน้าที่หลักของ package และไฟล์นี้
    *   มองหา Go-specific patterns (interfaces, concurrency, error handling, structured logging ฯลฯ)
    *   ระบุ "Best Practices" ที่ถูกนำมาใช้ (เช่น Clean Architecture, SOLID, Effective Go)
3.  **การอธิบาย (สไตล์ Senior สอน Junior)**:
    *   **สรุปภาพรวม (Overview)**: เริ่มต้นด้วยสรุปสั้นๆ ว่าโค้ดนี้ทำหน้าที่อะไรในภาษาที่เข้าใจง่าย
    *   **เจาะลึกการทำงาน (Walkthrough)**: อธิบายส่วนประกอบหลักของโค้ดทีละส่วน ไม่ใช่แค่บอกว่าโค้ดเขียนว่าอะไร แต่ให้บอกว่ามัน "ทำอะไรได้"
    *   **ทำไมต้องทำแบบนี้? (Best Practice)**: ส่วนนี้สำคัญที่สุด อธิบาย "เหตุผล" เบื้องหลังการเขียนโค้ดแบบนี้ เช่น:
        *   "เราใช้ interface ตรงนี้เพื่อให้เราสามารถทำ mock ในการทดสอบ (test) ได้ง่ายขึ้น"
        *   "เราใช้ `slog` สำหรับทำ structured logging เพราะมันเป็นมาตรฐานใหม่ของ Go ที่มีประสิทธิภาพ"
        *   "เราคืนค่า `error` เป็นลำดับสุดท้ายตามธรรมเนียมปฏิบัติ (Idiomatic Go) เพื่อให้ง่ายต่อการจัดการ"
    *   **คำแนะนำจาก Senior (Senior Tips)**: ให้คำแนะนำเพิ่มเติม 1-2 ข้อ หรือจุดที่ควรระวัง (Gotchas) ที่เกี่ยวข้องกับไฟล์นั้นๆ
4.  **ภาษาและโทน (Tone & Language)**:
    *   **ต้องตอบเป็นภาษาไทย** เท่านั้น
    *   ใช้โทนที่ให้กำลังใจและเป็นการสอนงาน (Mentoring)
    *   หลีกเลี่ยงศัพท์เทคนิคที่ยากเกินไปหากไม่จำเป็น หรือถ้าใช้ต้องอธิบายเพิ่ม
    *   ใช้การเปรียบเทียบ (Analogy) หากช่วยให้เข้าใจคอนเซปต์ที่ซับซ้อนได้ดีขึ้น
